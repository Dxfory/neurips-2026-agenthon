## 评分（当前 5.3.0；以下分析公式继承 5.2.2）

- 榜单分 = −0.27 + 1.27 × analysis。Final 另加 0.25 × reasoning，赛后按 `submitted_reasons` 评审。
- analysis = claim 系数 × (0.7 × PQ + 0.3 × IQ)。claim 逐条核对，假 claim 会拉低系数。
- PQ 以每个单元不公开的朴素规则为锚（朴素规则得 0.5）。
- IQ = min(naive_IS / (naive_IS + IS), max(0.5, PQ))，其中 IS = 区间宽度 + 20 × 漏出距离。

## 方法概要

代码先把能算的都算好，House 模型（Nemotron-3-Super-120B）只做有边界的判断。

1. **证据**：只读清单标给该实体（或标为共享）的、截止日前的文档；用 BM25 加金融关键句挑出片段。
2. **代码计算**：
   - 财报表格里的同期对比；
   - EPS 季节随机游走锚点（用 2010–2021 年的 SEC 财报校准）；
   - 宏观修正基准率（用 2003–2021 年的 ALFRED 实时 vintage 校准）；
   - 序列统计基线（方法按 2022 年前公开数据上的回放来选）；
   - CPI 汽油、能源和总项：用语料里的周度油价直推（本地线性模型，在 `models[]` 里披露）；
   - 波动尺度。
3. **模型**：
   - 1 次规划。规划先读原文；凭记忆写出的数字和截止日后的事件，由代码删掉。
   - 分析员分组调用，多次采样；分类题对有分歧的标签追加单实体投票。
   - 每个单元最多用 23 次请求（上限 25）。JSON 先在代码里恢复。
4. **合成与校准**：模型与代码基线按 50/50 合成；标签和区间出自同一个分布；区间系数按评分器的区间分，在 2022 年前的公开数据上校准。
5. **Claim**：全部是被引段落的逐字原文，而且只引清单标给该实体的文档。本次 11 个公开单元的确定性 claim 检查系数均为 1.0；没有据此声明隐藏任务或 NLI 评分结果。
6. **推理理由**：预测定稿后，由模型写 1–3 条 `submitted_reasons`，覆盖任务列出的驱动因素。理由的含义由代码对照答案检查；时间不够时由代码兜底生成。

历史校准主要使用 2021 年底及 2022 年初以前公开的数据；版本选择另参考了官方练习单元的 Dev 成绩，并按练习单元例外披露。不能把这两类依据统称为“所有选择只用 2022 年前数据”，也不能据公开题 cutoff 保证全部隐藏任务适用。来源、日期和选择记录见 `agent_v21_6/ARTIFACT_PROVENANCE.md` 与 `calib_data/README.md`；本轮日期资格修复见上方验收记录。

## 本地验证：没见过的题型

Final 有大量没公开的题型，还有反事实探针。我们用 2022 年前就已有结果的公开数据（FRED/ALFRED、美联储、SEC 10-Q 和 8-K 原文）造了 16 个新题型单元：

结果：

## 推理理由（Final 的 0.25 × reasoning）

Dev 不评推理理由，所以我们用代理评审（多票）比较了三种改写方案：
- v22：槽位模板；
- v23：自由写作加检查；
- v24：每个实体写一句。

v22 和 v24 都不如 v21 的自由写作加代码检查（配对 −0.09 和 −0.057）。v23 没测出有效结果。三者都没有采用。结论是：检查能约束 House 模型，模板反而伤害理由质量。

## 复现

以下命令都在 `T4/` 下运行，需要 Python 3.13，以及能构建 linux/amd64 镜像的 Docker。

```bash
git clone https://github.com/Agenthon-2026/Agenthon2026-public.git
git clone https://github.com/Agenthon-2026/track4-analysis-public.git
python3.13 -m venv .venv
.venv/bin/pip install "qfbench2-common @ git+https://github.com/Agenthon-2026/Agenthon2026-public.git@50fb2dc#subdirectory=common" numpy jsonschema requests pytest
```

```bash
# 离线测试。没有 calib_data/ 和 units_pre2022/ 时，相关测试自动跳过（全新环境：239 通过，7 跳过）。
# 先把 TMPDIR 设到 agent 目录之外，否则 pytest 的临时目录可能落进 agent 目录
(cd agent_v21_10 && ../.venv/bin/python -m pytest -q -p no:cacheprovider tests)
# 跑公开单元，不调用模型（只走兜底路径），跑完做官方检查
(cd agent_v21_10 && ../.venv/bin/python tools/run_units.py --offline)
# 构建镜像，在受限容器里验证全部公开单元（约 1 分钟；加 --live <unit> 会再接模型跑一个单元）
bash sub/tools/build_local.sh agent_v21_10 t4agent-v21_10:21.10.0 verification-v21_10
.venv/bin/python -u sub/tools/verify_local.py --build agent_v21_10 --image t4agent-v21_10:21.10.0 \
  --verification verification-v21_10 --workers 3
# 打包时 --build 和 --verification 必须显式写（pack.py 的缺省值是 agent_v2）
```

需要密钥的操作：
- **接模型运行**：把 OpenRouter key 放在 `T4/.openrouter.env`（权限 600，不入库）。`tools/run_units.py --parallel 2 --prod-clocks` 默认用免费的 Nemotron 端点。每个账号每天 1,000 次；`--rpm` 默认每分钟 18 次，几个运行共用一个 key 时，总数控制在每分钟 20 次以内。
- **重建压力单元**：需要 `T4/.fred.env`（FRED API key）和 `T4/.sec.env`（SEC 要求的 User-Agent 联系方式）。
- **推送和打包**：需要 `docker login -u greedyshark` 和 `T4/.env` 里的 Team Key，命令见 `sub/PIPELINE.md`。ZIP 里要写 linux/amd64 的 manifest digest，不能用 `docker push` 打印的 index digest。

## 官方 2026-10-07 的新说明与本版本的关系

- **Final 不能运行声明了 Docker `VOLUME` 的镜像（包括从基础镜像继承的）。** v21.10、v21.8、v21.7、v21.3 和 v21.2 的镜像都没有 `VOLUME`。`sub/tools/verify_local.py` 现在会检查这一点，结果写进 `image-inspect.json`。
- **NeMo Retriever 嵌入模型是唯一允许放进镜像的神经模型。** 我们的检索用 BM25，镜像里没有任何模型权重，不受影响。
- **复核会用新的 `QFBENCH_SEED` 重跑，T4 按 bootstrap 置信区间是否重叠来比较。** 官方说明：想让种子在重跑时保持不变，就必须在代码里写成常数。v21.3 发给 House 模型的 seed 取自 `QFBENCH_SEED`，所以重跑时模型采样会不同。v21.5 已改为代码常量 `SEED = 0`（派生的各次调用种子与历次验证时 `QFBENCH_SEED=0` 相同）；v21.7 起镜像另设 `PYTHONHASHSEED=0`，集合遍历顺序、也就是提示内容，重跑时也不变。
